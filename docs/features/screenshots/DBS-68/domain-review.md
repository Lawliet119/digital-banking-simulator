| 1 | blocking | §1 Q4, §3 "Quyền của role deploy", TC-68-12 | The RunTask condition is written as `ecs:cluster = dbs-dev`. | 4 | should-fix | §2 "Chạy hai lần liên tiếp" | The claim "`concurrency` không cho hai lần chạy song song" covers only `deploy.yml`. The pipeline then fails for a reason unrelated to the migration. | `deploy.yml` `concurrency: deploy-dev`. `migrate.sh` is stateless per §2. | Before `run-task`, call `list-tasks --started-by 'migrate-*'` (or filter by family `dbs-migrate` with `desired-status RUNNING`) and refuse to run while one is running. | 5 | should-fix | §2 table, rows "Quá deadline" and "Container thoát khác 0" | The `stop-task` path is not specified: (a) The script must wait until the task is STOPPED before exiting 1. (b) `stop-task` on a task that stopped just now (race at the deadline) can return an error or succeed with an already STOPPED task. That error must not hide the real exit code. (c) After SIGTERM then SIGKILL the container exitCode is 137 and `stopCode = UserInitiated`. The log message must say "quá hạn", not "migration lỗi". (d) A task that never leaves PROVISIONING/PENDING is also covered by the same deadline, but TC-68-05 tests only `RUNNING`. | The §4 TC-68-05 text says "Task RUNNING quá MIGRATE_DEADLINE_SECONDS". `deploy.sh` has no such handling. | Add cases: stuck PENDING/PROVISIONING past the deadline; stop-task returns an error because the task already STOPPED with exitCode 0 (should decide by exitCode); wait-for-STOPPED after stop. |

| 7 | should-fix | §2 (b), §3, "log lỗi vào public CI logs" | The claim "không chứa mật khẩu" is not sufficient. Add a test with a log line `::set-output::` and `::error::`. |
