**Claims checked, no problem found:**

- **(a)** The image cannot carry `.auth-local/`: the runtime stage sets `NODE_ENV=production` and copies only `dist`, `node_modules` and `package.json`. Only the list of copied files in the doc is wrong (row 9).
- **(b)** Holds. In `infra/terraform/envs/dev/session/ecs.tf` (L36, L103) both the api and migration tasks pass `NODE_ENV = var.node_env`. `variables.tf` L49 restricts that to `staging`/`production`, and nothing else in `infra/` sets `NODE_ENV` or `AUTH_*`.
- **(c)** Defaulting `AUTH_MODE` to `cognito` breaks none of the code that sets `COGNITO_*`:
  - `validation.schema.spec`, `env.bootstrap.spec`, `jwks-verifier.service.spec`, `test/db/invariants.db-spec.ts` and `manual-smoke.dbs51` keep working.
  - `test/support/invariants.ts` extracts only the DB keys.
  - `env/.env.example` leaves `COGNITO_*` commented out.
- **Names that exist as the doc says:** `ErrorCode` `UNAUTHENTICATED`, `TOKEN_EXPIRED` and `FORBIDDEN`; the route `GET /v1/identity/me` (URI versioning, default `1`); `ts-node`, `tsconfig-paths`, `jose` and `cross-env`; the Swagger bearer scheme `access-token`.
- **Money and state:** not applicable. The only side effect is that a local token creates `users` rows through `ON CONFLICT (cognito_sub) DO NOTHING`, and only in local environments.
- **Hand-offs:** none.
