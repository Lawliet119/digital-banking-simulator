Checked against source and probes, and correct as the design states:
- **Bootstrap order:** putting process-logging between `env` and `bigint` keeps TC-22-25 passing (`main-wiring.spec.ts` only checks env &lt; bigint &lt; `await import('./app.module')`).
- **Root logger:** nestjs-pino's root is whoever reaches `ensureLoggerMiddleware` first (`rootLogger.js`), so the `LoggingModule` `pinoHttp` config has no effect.
- **`invalidKeys`:** they come only from Joi `path[0]`, i.e. schema key names. `allowUnknown` keeps keys outside the schema out, and values appear only in `message`. On startup, Nest's `ExceptionHandler` logs the error object, which is reduced to `errorType` (`exceptions-zone.js`, `exception-handler.js`).

No DBS-43 work is mixed in, and no transaction boundary or HTTP contract changes, apart from finding 1.
