Checked and found no problem:
- **Module boundary:** importing `@config/compose-database-url` from `test/**` is allowed. The ESLint config on origin/main restricts imports only under `src/**`, and tsconfig has the `@config/*` path.
- **No secrets in the names:** the variable names come from a fixed list, and `allowUnknown` is set, so no value or secret can leak through `invalid`.
- **Composed URL:** it encodes user, password and database name, and checks the host against a pattern, so it cannot add TLS parameters.
- **Starting ts-node with `process.execPath -r … -r …`:** with cwd `backend` this follows the same pattern as `logging-driver.ts` and TC-69-19. Paths from `require.resolve` work on Windows without a shell.
