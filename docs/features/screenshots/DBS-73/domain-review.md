Checked and resolved:
- V3-1 (aside from finding 1): `sqs:ListQueues` is an account-level action with no resource type in IAM, so it is granted only on `"*"`. A queue policy only applies to requests aimed at that queue's ARN (the doc's §3 queue policy has `Deny sqs:*` and is attached to each of the 4 queues). `ListQueues` is not checked against any queue policy, and `--queue-name-prefix` is only a server-side filter that needs no per-queue permission. The control and the `sqs:*` grant sit in the same inline policy, so when `list-queues` succeeds the whole document is in effect. A later `AccessDenied` on the 4 calls is therefore the explicit Deny, not IAM delay. Recording the full error text and not depending on the "explicit deny" wording is correct.
- V3-2: The "one redrive per message" rule and the reason for it (back in the DLQ means it can live until about T0 + 12 days) are correct. Live relay traffic giving a false "not met" errs on the safe side. Only the check's timing is left (finding 2).

Verdict: REVISE
