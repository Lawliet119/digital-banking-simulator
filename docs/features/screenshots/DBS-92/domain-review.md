| 2 | should-fix | §2.6, §3 | There is no batch SQL for `processed_events`, and §2.6 drops `FOR UPDATE` and `SKIP LOCKED`. The second DELETE waits on the first's row locks, up to `lock_timeout` 2 s, and then deletes 0 rows. Under rule 2.4 that looks like "nothing left", so the run ends early with rows remaining.
