I found no money or idempotency errors in the merged code:
- **One transaction:** the `processed_events` claim and the INSERTs into `notification_log` commit or roll back together.
- **Duplicates:** a redelivered event finds the claim and writes nothing more (TC-102-05, TC-104-01).
- **Missing user:** the whole event rolls back.
- **Retry timing:** the delays are 5/10/20/40 s. There is no backoff on receive 5 or for poison messages, and an error from `changeVisibility` never hides the original error.
- **BR-13:** messages are fixed sentences chosen only from `eventType`, `type` and `newStatus`.
- **Logs:** they hold only `eventId`, `eventType` and `correlationId`.
- **Names:** the `kind` values match the table's CHECK constraint, and the field names match the event contract.
